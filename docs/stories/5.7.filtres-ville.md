# Story 5.7: Filtres par ville — Candidats & Offres

## Status

TODO

## Story

**As a** recruiter,
**I want** to filter candidates and job offers by structured city,
**so that** I can narrow down results to specific locations.

## Acceptance Criteria

1. Filtre ville sur liste candidats : champ texte libre remplacé par `CityAutocomplete` (`mode="multi"`)
2. Procédure `candidate.list` : paramètre `city: string` remplacé par `cityIds: string[]`
3. Filtre `cityIds` en OR : `candidate.cities.some({ cityId: { in: cityIds } })`
4. Procédure `candidate.listCities` (renvoyait des strings distinctes) supprimée — plus utilisée
5. Filtre ville sur liste offres : champ texte libre remplacé par `CityAutocomplete` (`mode="single"`)
6. Procédure `jobOffer.list` : paramètre `location: string` remplacé par `cityId: string | null`
7. Filtre `jobOffer.list` par `cityId` : `WHERE JobOffer.cityId = cityId`
8. URL query params mis à jour : `cityIds` contient des UUIDs (pas des noms)
9. Chips actifs affichent le nom résolu de la ville (depuis le state local du filtre)
10. Tests : `candidate.list({ cityIds: [idParis] })` retourne uniquement les candidats avec Paris

## Dev Notes

### Previous Story Insights

- Stories 5.4 et 5.5 terminées : `candidate.cities` (relation) et `jobOffer.cityId` (FK) sont en place
- La procédure `candidate.listCities` existait pour alimenter l'ancien filtre texte — elle est supprimée ici. Vérifier qu'aucun composant frontend ne l'appelle encore avant de la supprimer.
- Le filtre existant sur `candidate.list` utilisait `city: string` avec `contains + mode: 'insensitive'` — remplacer par la logique `cityIds` OR.

### API Specifications

**`candidate.list` input (extrait) :**
```ts
// Avant
city: z.string().optional()
// Après
cityIds: z.array(z.uuid()).default([])
```

**Logique OR pour les candidats :**  
Un candidat est inclus s'il a **au moins une** de ses villes dans `cityIds`. Cela correspond à `some` dans Prisma.

**`jobOffer.list` input (extrait) :**
```ts
// Avant
location: z.string().optional()
// Après
cityId: z.uuid().optional().nullable()
```

### Technical Constraints

- `cityIds` dans les URL params : si le projet encode déjà les arrays en CSV (`?tags=id1,id2`), suivre la même convention. Sinon utiliser `?cityIds[]=id1&cityIds[]=id2`.
- Les chips actifs doivent afficher le **nom** de la ville (pas l'UUID). Ces noms viennent du state local `selectedCities` — pas besoin d'un appel supplémentaire.
- Invalider `utils.candidate.list.invalidate()` et `utils.jobOffer.list.invalidate()` si nécessaire lors du changement de filtre.
