# Story 4.4: Candidate Sharing - URL Generation

## Status

DONE

## Story

**As a** recruiter,  
**I want** to generate a shareable URL for a candidate profile,  
**so that** I can send it to clients.

## Acceptance Criteria

1. "Partager" button on candidate detail page  
2. Click opens sharing modal/popover  
3. Two options: "Fiche complète" and "Fiche anonymisée"  
4. Generate unique share token for each type  
5. Share URL format: `/share/[token]`  
6. Token stored in database with: candidateId, type (normal/anonymous), createdAt, expiresAt  
7. Copy URL button with success toast "Lien copié!"  
8. Display generated URL in modal  
9. Option to set expiration (7 days, 30 days, never) - default 30 days  
10. Previous share links listed in modal (reuse or regenerate)  
11. Rate limiting sur la création de liens : max 20 liens de partage créés par utilisateur par heure ; en cas de dépassement, message « Trop de requêtes. Réessayez dans quelques minutes. » (réf. `rate-limiting.md` §3.2)

**Réf.** PRD `docs/prd.md` § Epic 4, Story 4.4 ; Wireframes « Modal Partager » ; Architecture router `shareLink`, modèle ShareLink ; `docs/architecture/rate-limiting.md` §3.2 (partage par userId).

## QA Results

### Code Review — 2026-04-04

**Reviewer :** claude-sonnet-4-6

#### Points positifs

- **Ordre d'exécution correct dans `create`** : rate limit → vérification de propriété → écriture DB. Fail-fast sans consommer de ressources inutiles.
- **Isolation multi-tenant robuste** : les deux procédures (`create` et `listByCandidate`) vérifient explicitement `candidate.companyId = ctx.companyId` avant tout accès aux `ShareLink`.
- **DRY effectif** : `EXPIRATION_LABELS`, `TYPE_LABELS`, et les schémas Zod sont centralisés dans `src/lib/validations/shareLink.ts`, partagés entre le router, le composant et les tests.
- **UX loading** : bouton "Générer un lien" désactivé pendant `isPending`, libellé remplacé par "Génération…".
- **Accessibilité** : `aria-label` sur les boutons Copier / Ouvrir, `sr-only` sur la `DialogDescription`, labels explicites sur les selects.
- **Requête conditionnelle** : `{ enabled: open }` sur `listByCandidate` — évite un appel réseau inutile à chaque montage du dialog.
- **Couverture de tests** : intégration (9 cas) + composants (9 cas) couvrent tous les chemins fonctionnels et les cas d'erreur.

#### Points à surveiller

- **Rate limiter in-memory** : `checkRateLimit` utilise un `Map` node.js local. En environnement serverless multi-instances (Vercel), la limite de 20 req/h est par instance, pas globale. Acceptable pour un MVP ; à remplacer par un store distribué (Redis/Upstash) en production à fort trafic.
- **`ctx.user!.id` non-null assertion** : nécessite que `protectedProcedure` garantisse `user` non-null quand `companyId` est défini (vérifié dans `context.ts`). Le commentaire justificatif est en place.
- **`buildShareUrl` et `window.location.origin`** : ne doit être appelé que dans des callbacks (jamais au render top-level). C'est le cas actuellement ; à maintenir si le composant évolue.
