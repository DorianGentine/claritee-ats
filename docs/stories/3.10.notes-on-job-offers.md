# Story 3.10: Notes on Job Offers

## Status

DONE

## Story

**As a** recruiter,
**I want** to add notes on job offers,
**so that** I can document client requirements and updates.

## Acceptance Criteria

1. La fiche offre `/offers/[id]` comporte une **section Notes** dédiée, visible pour tous les utilisateurs du cabinet
2. Le système de notes réutilise le **même modèle et la même logique** que pour les notes sur candidats (Story 3.9), en attachant cette fois les notes à une offre (champ `offerId`)
3. Un champ ou bouton **"Ajouter une note"** permet de créer une nouvelle note sur l'offre directement depuis la fiche offre
4. Le contenu de la note est saisi via un **éditeur riche BlockNote** (même système que pour les notes candidats : blocs texte, listes, titres — inspiration Notion)
5. Chaque note stocke les métadonnées suivantes : **auteur** (utilisateur), `createdAt` (date/heure de création)
6. Les notes sont stockées et affichées sur la fiche offre en **flux type chat**, comme sur les fiches candidats (ordre chronologique naturel en lecture, basé sur `createdAt asc`)
7. Un utilisateur peut **éditer uniquement ses propres notes** (pas celles des autres utilisateurs)
8. Un utilisateur peut **supprimer ses propres notes** avec confirmation (dialogue de confirmation avant suppression)
9. Les notes sont **partagées au niveau du cabinet** : toutes les notes d'une offre sont visibles par tous les utilisateurs de la même `companyId`
10. Si aucune note n'existe pour une offre, la section affiche un **état vide** clair (ex. "Aucune note") avec un call-to-action vers la création d'une première note

**Réf.** PRD § Epic 3, Story 3.10 ; Architecture §5 (Note), §9 (router `note`) ; Design System §2 (typographie) ; Wireframes §5 section Notes (fiche offre).

> Note :
> - Cette story réutilise le modèle `Note` introduit pour les **notes sur candidats** (Story 3.9), en ajoutant la vue et les actions côté offre.
> - Le widget de note rapide (Story 3.11) et la page "Mes notes" (Story 3.12) réutiliseront également ce modèle mais ne sont pas dans le périmètre ici.

## Dev Notes

### Dependencies & Previous Stories

- **Story 3.6** : fiche offre détaillée `/offers/[id]` (structure de la page, sections header / détails / candidats / tags).
- **Story 3.9** : notes sur candidats (modèle `Note`, router `note`, section Notes sur la fiche candidat, éditeur riche BlockNote).
- Cette Story 3.10 étend l'usage du modèle `Note` aux **offres**, en gardant un contenu texte simple côté offre, tout en partageant l'API et les règles de permissions.

### Data Models

- **Note** (rappel / complétion) :
  - `id` (UUID)
  - `content` (texte ; pour les offres, plain text)
  - `authorId` (FK `User`)
  - `candidateId` (FK `Candidate`, nullable)
  - `offerId` (FK `JobOffer`, nullable)
  - `companyId` (FK `Company`)
  - `createdAt`, `updatedAt`
- Invariants pour cette story :
  - Pour une note d'offre : `offerId` non nul, `candidateId` null.
  - Les notes sont toujours scopées par `companyId`.

### API Specifications

- **note.listByOffer** :
  - Input : `{ offerId: z.uuid() }`.
  - Comportement :
    - Vérifier que l'offre appartient au `companyId` courant (lève `NOT_FOUND` sinon).
    - Retourner toutes les notes associées, triées par `createdAt` asc (flux type chat).
- **note.create** (réutilisé avec `offerId`) :
  - Input : `{ offerId: z.uuid(), content: z.string().min(1) }`.
  - Comportement :
    - Vérifier `companyId` de l'offre.
    - Créer une note avec `offerId`, `candidateId = null`, `authorId = ctx.user.id`, `companyId = ctx.companyId`.
- **note.update** / **note.delete** :
  - Contrôler que `authorId === ctx.user.id` et que `companyId` correspond ; sinon renvoyer une erreur UNAUTHORIZED/NOT_FOUND.

### UI & Components

- **`src/components/shared/NotesSection.tsx`** : composant partagé (DRY) contenant toute l'UI chat — réutilisé par fiche candidat et fiche offre. Props : `notes`, `isLoading`, `currentUserId`, callbacks `onCreateNote(content, onSuccess)`, `onUpdateNote(id, content, onSuccess)`, `onDeleteNote(id, onSuccess)`, flags `*Pending`.
- **`src/components/offers/OfferNotesSection.tsx`** : wrapper léger qui branche `note.listByOffer`, `note.create`, `note.update`, `note.delete` avec toasts et passe les données à `NotesSection`.
- **`src/components/candidates/CandidateNotesSection.tsx`** : refactorisé de la même façon pour réutiliser `NotesSection`.

### Testing

- Prioriser les scénarios critiques :
  - Création / édition / suppression de notes sur une offre par l'auteur.
  - Accès en lecture pour tous les utilisateurs du même cabinet, interdiction pour un autre cabinet (multi‑tenancy).
  - Comportement en absence de notes (état vide).
- Vérifier la cohérence visuelle et UX entre fiche offre et fiche candidat.
