# Story 4.5: Public Candidate Page - Normal Version

## Status

DONE

## Story

**As a** client,  
**I want** to view a shared candidate profile without logging in,  
**so that** I can review candidates sent by the recruiter.

## Acceptance Criteria

1. Public route `/share/[token]` accessible without authentication  
2. Validates token exists and not expired  
3. Displays candidate profile in CV layout (same as internal view)  
4. Shows: photo, full name, title, city, summary, experiences, formations, languages  
5. Contact info visible: email, phone, LinkedIn  
6. Does NOT show: notes, tags, associated offers, internal data  
7. Company branding/logo displayed (recruiter's company)  
8. Clean, professional design optimized for client viewing  
9. Expired/invalid token shows friendly error page  
10. Mobile-responsive layout  

**Réf.** PRD `docs/prd.md` § Epic 4, Story 4.5 ; Wireframes §8 Page Partage Public (version normale) ; route `src/app/share/[token]/` [Source: docs/architecture.md §6, docs/frontend-architecture.md §2]

## Dev Notes

### Previous Story Insights

- Story **4.4** : génération des liens `ShareLink`, tokens stockés, types `NORMAL` / `ANONYMOUS` ; cette story consomme ces données côté public
- Stories **2.4** / fiche candidat : référence UX pour le layout CV interne à adapter en mode public

### Data Models

- `ShareLink` : `token`, `type`, `expiresAt`, `candidateId` [Source: prisma/schema.prisma]
- `Candidate` : champs publics autorisés explicitement dans le DTO (pas de fuite de relations sensibles)

### API Specifications

- Procédure publique **sans** `ctx.companyId` utilisateur : la confiance repose sur le **token opaque** + validation expiration + filtrage strict des champs retournés [Source: docs/architecture.md §4, §10.1]
- Ne jamais réutiliser une query `candidate.getById` protégée telle quelle pour la page publique

### Component Specifications

- Réutiliser / factoriser les blocs d’affichage CV (DRY) plutôt que dupliquer toute la fiche [Source: docs/frontend-architecture.md §4.4]
- Pas de barre d’actions recruteur (modifier, supprimer, notes)

### File Locations

| Rôle | Chemin probable |
|------|-----------------|
| Page publique | `src/app/share/[token]/page.tsx` |
| Layout optionnel | `src/app/share/[token]/layout.tsx` ou `src/app/share/layout.tsx` |
| Composants vue publique | `src/components/share/` ou `src/components/candidates/` (préfixe `Public` si besoin) |
| Router tRPC | `src/server/trpc/routers/shareLink.ts` |
| Proxy / routes publiques | `src/proxy.ts` |

### Technical Constraints

- **Sécurité** : surface d’attaque = token deviné ; tokens doivent rester suffisamment entropiques (déjà gérés en 4.4) [Source: docs/architecture.md §10.1]
- **RGPD** : page publique = données personnelles ; respecter le périmètre affiché (AC 6)

### Testing

- Priorité : intégration sur la résolution token + tests de non‑régression sur l’absence de champs internes dans la réponse

### Project Structure Notes

- La Story **4.6** étendra la même route ou la même procédure pour le rendu **anonyme** ; anticiper une séparation claire `normal` vs `anonymous` dans le code pour limiter le refactor

## QA Results

### Code Review — 2026-04-04

**Reviewer :** claude-sonnet-4-6

#### Points positifs

- **DTO strict** : `select` Prisma explicite dans les deux contextes (page SSR + procédure tRPC) — aucun champ interne (`notes`, `tags`, `candidatures`, `cvUrl`) n'est exposé.
- **Ordre des vérifications** dans `getPublicByToken` : `!link` → type check → expiry. L'ordre ne révèle pas l'existence d'un token ANONYMOUS.
- **SSR propre** : Server Component avec requête Prisma directe, pas de round-trip tRPC client. Bon TTFB et SEO.
- **`notFound()` retourne `never`** : TypeScript rétrécit correctement, pas d'assertion nécessaire.
- **`ShareErrorState`** : variant `"not-found"` | `"expired"`, réutilisable pour Story 4.6 sans modification.
- **DRY sur `CandidateDetailHeader`** : réutilisé tel quel depuis la fiche interne.
- **Couverture** : 12 tests RTL + 4 tests d'intégration, TypeScript 0 erreur.

#### Points à surveiller

1. **Duplication du `select` Prisma** entre `page.tsx` et `getPublicByToken` — si un champ public évolue, mettre à jour les deux endroits. Extraire une constante `publicCandidateSelect` si la shape bouge (ex. en Story 4.6).
2. **`LANGUAGE_LEVEL_LABELS` sous-typé** dans `PublicCandidateProfile` (`Record<string, string>` vs `Record<EnumKey, string>` dans la fiche interne) — le fallback `?? lang.level` compense au runtime.
3. **Metadata statique** : `<title>` ne contient pas le nom du candidat — acceptable pour un MVP où les pages partagées ne sont pas indexées ; à améliorer avec `generateMetadata` si besoin.
