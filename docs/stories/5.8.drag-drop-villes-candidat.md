# Story 5.8: Drag & Drop villes candidat (dnd-kit)

## Status

review

## Story

**As a** recruiter,
**I want** to reorder candidate cities by drag & drop,
**so that** city prioritization feels natural and fast.

## Acceptance Criteria

1. Packages installés en versions exactes : `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities`
2. `CityAutocomplete` en `mode="multi"` avec `ordered={true}` : chips devenus draggables via `SortableContext` + `useSortable`
3. Handle de drag visible (icône grip — `GripVertical` de `lucide-react`) à gauche de chaque chip
4. Boutons ↑↓ de la story 5.3 retirés — remplacés par le drag & drop
5. L'ordre est mis à jour localement (optimiste) dès le drop via `onChange`
6. Le nouvel ordre est persisté via `candidate.update` à la soumission du formulaire candidat (pas de mutation à chaque drop)
7. Accessible au clavier : espace pour saisir un item, flèches pour déplacer, espace pour déposer
8. En mode `ordered={false}` (`ClientCompany`) : aucun drag & drop, comportement inchangé
9. Tests : simulateur dnd-kit → `onChange` appelé avec les villes dans le bon ordre

### Component Specifications

**Packages dnd-kit :**
- `@dnd-kit/core` : `DndContext`, `useSensors`, `useSensor`, `PointerSensor`, `KeyboardSensor`
- `@dnd-kit/sortable` : `SortableContext`, `useSortable`, `rectSortingStrategy`, `arrayMove`, `sortableKeyboardCoordinates`
- `@dnd-kit/utilities` : `CSS` (pour `transform` dans le style du composant draggable)

**Structure `SortableCityChip` :**
```tsx
const SortableCityChip = ({ city, onRemove }: { city: CityOption; onRemove: () => void }) => {
  const { attributes, listeners, setNodeRef, transform, transition, isDragging } = useSortable({ id: city.id })
  const style = { transform: CSS.Transform.toString(transform), transition, opacity: isDragging ? 0.5 : 1 }
  return (
    <div ref={setNodeRef} style={style} className="flex items-center gap-1 ...">
      <GripVertical className="cursor-grab" {...attributes} {...listeners} />
      <span>{city.name}</span>
      <button onClick={onRemove}>×</button>
    </div>
  )
}
```

### Completion Notes List

- **Versions installées (exactes)** : `@dnd-kit/core@6.3.1`, `@dnd-kit/sortable@10.0.0`, `@dnd-kit/utilities@3.2.2`.
- **Stratégie `rectSortingStrategy`** (et non `verticalListSortingStrategy` comme suggéré dans la story) : les chips sont disposées en ligne avec retour à la ligne (`flex-wrap`), la stratégie verticale donnerait des animations incohérentes. Au clavier, ce sont donc les flèches **gauche/droite** (et haut/bas pour changer de ligne) qui déplacent la chip.
- **Poignée = vrai `<button>`** (`aria-label="Déplacer <ville>"`) portant `attributes` + `listeners` via `setActivatorNodeRef` : focusable au clavier, désactivée quand le composant est `disabled`. `PointerSensor` avec une distance d'activation de 5 px pour qu'un simple clic ne démarre pas de drag.
- **Annonces lecteur d'écran en français** (`accessibility.announcements` + `screenReaderInstructions`, et `roleDescription` « ville réordonnable » sur les poignées) — dnd-kit les fournit en anglais par défaut.
- **AC 6 — persistance** : option 2 de la Task 3 retenue. Le drop met à jour l'état local via `onChange` (optimiste) ; la persistance se fait au submit du formulaire candidat (`candidate.update` reçoit déjà les villes ordonnées depuis la story 5.4). Un appel `candidate.update` à chaque drop n'aurait pas de sens en création (candidat inexistant) et contournerait le bouton « Enregistrer » en édition.
- **`ordered={false}`** (entreprise cliente) : ni `DndContext` ni poignée rendus, chip inchangée (nom + ×).
- **Tests** : les tests ↑↓ sont remplacés par des scénarios clavier réels dnd-kit (espace → flèche → espace / Échap) avec un layout mocké (`getBoundingClientRect`) puisque jsdom ne calcule pas de positions.
