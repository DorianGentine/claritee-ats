# Story 4.7: Dashboard Metrics

## Status

DONE

## Story

**As a** recruiter,
**I want** the dashboard to show real metrics,
**so that** I have an overview of my cabinet's activity.

## Acceptance Criteria

1. Dashboard cards now show real counts:
   - Total candidats
   - Offres actives (status `IN_PROGRESS`)
   - Total clients
2. Recent activity section:
   - Last 5 candidates added (nom, date)
   - Last 5 notes created (entité associée, date)
3. Quick stats per offer status (counts per `JobOfferStatus` value: `TODO`, `IN_PROGRESS`, `DONE`)
4. "Candidats partagés ce mois" count (ShareLinks créés depuis le 1er du mois courant)
5. Click on metric card navigates to relevant list (`/candidates`, `/offers`, `/clients`)
6. Data refreshed every 10 minutes — `staleTime: 10 * 60 * 1000` sur la query dashboard
7. Empty states handled gracefully (sections vides affichent un message neutre)
8. Performance: dashboard loads in < 1 second (toutes les requêtes parallèles dans un `Promise.all`)
9. Cached queries where appropriate — `staleTime: 10 * 60 * 1000` (override du global 5min)
10. Welcome message if all metrics are zero (hint d'onboarding avec CTA vers `/candidates/new` et `/offers/new`)

**Réf.** PRD `docs/prd/epic-4-recherche-filtres-partage.md` § Story 4.7 ; Wireframes §1 Dashboard ; Architecture §9 (queries agrégées par companyId) [Source: docs/architecture/9-api-trpc-organisation-des-routers.md]

## Dev Notes

### État actuel de la page (`src/app/(dashboard)/dashboard/page.tsx`)

La page est un **Server Component** avec :
- Trois `<article>` avec counts hardcodés à `0`
- Deux boutons **disabled** (`"Nouveau candidat"`, `"Nouvelle offre"`)
- Un message statique `"Ajoutez votre premier candidat…"`

La story **remplace entièrement** le contenu dynamique par `<DashboardMetrics />` en conservant uniquement le `<h1>` et le wrapper `max-w-6xl`.

### Architecture du nouveau router

```ts
// src/server/trpc/routers/dashboard.ts
import { router, protectedProcedure } from "../trpc"

export const dashboardRouter = router({
  getStats: protectedProcedure.query(async ({ ctx }) => {
    const now = new Date()
    const startOfMonth = new Date(now.getFullYear(), now.getMonth(), 1)

    const [
      totalCandidates,
      activeOffers,
      totalClients,
      offerStatusCounts,
      sharedThisMonth,
      recentCandidates,
      recentNotes,
    ] = await Promise.all([
      ctx.db.candidate.count({ where: { companyId: ctx.companyId } }),
      ctx.db.jobOffer.count({ where: { companyId: ctx.companyId, status: "IN_PROGRESS" } }),
      ctx.db.clientCompany.count({ where: { companyId: ctx.companyId } }),
      ctx.db.jobOffer.groupBy({
        by: ["status"],
        where: { companyId: ctx.companyId },
        _count: { id: true },
      }),
      ctx.db.shareLink.count({
        where: {
          candidate: { companyId: ctx.companyId },
          createdAt: { gte: startOfMonth },
        },
      }),
      ctx.db.candidate.findMany({
        where: { companyId: ctx.companyId },
        orderBy: { createdAt: "desc" },
        take: 5,
        select: { id: true, firstName: true, lastName: true, createdAt: true },
      }),
      ctx.db.note.findMany({
        where: { companyId: ctx.companyId },
        orderBy: { createdAt: "desc" },
        take: 5,
        select: {
          id: true,
          title: true,
          createdAt: true,
          candidateId: true,
          offerId: true,
          candidate: { select: { firstName: true, lastName: true } },
          jobOffer: { select: { title: true } },
        },
      }),
    ])

    return {
      totalCandidates,
      activeOffers,
      totalClients,
      offerStatusCounts,
      sharedThisMonth,
      recentCandidates,
      recentNotes,
    }
  }),
})
```

**Attention :** `groupBy` n'est pas compatible avec `$transaction` Prisma — utiliser `Promise.all`.

### Points techniques critiques

- **`ShareLink` n'a pas de `companyId` direct** : filtrer via `candidate: { companyId: ctx.companyId }` (relation Prisma)
- **`offerStatusCounts` (groupBy)** : retourne un tableau `{ status, _count: { id: number } }[]`. Les statuts sans offres sont **absents** — l'UI doit normaliser pour toujours afficher les 3 valeurs (`TODO`, `IN_PROGRESS`, `DONE`) même à 0
- **`staleTime: 10 * 60 * 1000`** sur la query dashboard client : override le global 5min — les métriques sont rafraîchies toutes les 10 minutes (AC 6 & 9)
- **`isLoading` pas `isFetching`** pour les skeletons (convention projet — `isFetching` est vrai lors des revalidations silencieuses)
- **`Note.content`** est du JSON BlockNote — ne pas l'afficher brut. Utiliser `note.title` (optionnel) ou dériver "Note sur [candidat/offre]" depuis les relations incluses dans le select

### Normalisation des statuts d'offres (UI)

```ts
const STATUS_LABELS: Record<string, string> = {
  TODO: "À traiter",
  IN_PROGRESS: "En cours",
  DONE: "Terminées",
}

const ALL_STATUSES = ["TODO", "IN_PROGRESS", "DONE"] as const

const normalizedCounts = ALL_STATUSES.map((status) => ({
  status,
  label: STATUS_LABELS[status],
  count: offerStatusCounts.find((s) => s.status === status)?._count.id ?? 0,
}))
```
