# Story 4.8: Settings & Company Management

## Status

DONE

## Story

**As a** cabinet admin,
**I want** to manage my company settings and team,
**so that** I can maintain my cabinet's configuration.

## Acceptance Criteria

1. Settings page accessible from navigation (route `/settings`)
2. Company info section: edit company name (SIREN read-only)
3. Team section: list of all users in company
4. Show user: name, email, join date
5. Pending invitations list with expiration date
6. Generate new invitation URL button
7. Revoke pending invitation button
8. Cannot remove yourself from company (no user deletion in MVP — AC by omission: no delete button)
9. No role management in MVP (all users equal)
10. Profile section: edit own firstName, lastName
11. Change password functionality (Supabase Auth, client-side)

> **Note AC 10 :** email change déclenche un flow de confirmation Supabase (email envoyé à la nouvelle adresse) — hors scope MVP. Le champ email est affiché en lecture seule dans le profil.

### Procédures tRPC à ajouter

```ts
// src/server/trpc/routers/company.ts — COMPLÉTER (ne pas recréer)

updateCompany: protectedProcedure
  .input(updateCompanySchema)
  .mutation(async ({ ctx, input }) => {
    return ctx.db.company.update({
      where: { id: ctx.companyId },
      data: { name: input.name },
      select: { id: true, name: true, siren: true },
    });
  }),

listUsers: protectedProcedure.query(async ({ ctx }) => {
  return ctx.db.user.findMany({
    where: { companyId: ctx.companyId },
    select: { id: true, firstName: true, lastName: true, email: true, createdAt: true },
    orderBy: { createdAt: "asc" },
  });
}),
```

```ts
// src/server/trpc/routers/auth.ts — COMPLÉTER (ajouter après register)
// Importer en tête : import { protectedProcedure } from "../trpc"
// Importer : import { updateProfileSchema } from "@/lib/validations/user"
// Importer : import { createAdminClient } from "@/lib/supabase/admin"

getMe: protectedProcedure.query(async ({ ctx }) => {
  const user = await ctx.db.user.findUnique({
    where: { id: ctx.user.id },
    select: { id: true, firstName: true, lastName: true, email: true },
  });
  if (!user) throw new TRPCError({ code: "NOT_FOUND" });
  return user;
}),

updateProfile: protectedProcedure
  .input(updateProfileSchema)
  .mutation(async ({ ctx, input }) => {
    await ctx.db.user.update({
      where: { id: ctx.user.id },
      data: { firstName: input.firstName, lastName: input.lastName },
    });
    // Sync Supabase user_metadata pour que SiteNavbar reflète le changement
    const supabaseAdmin = createAdminClient();
    await supabaseAdmin.auth.admin.updateUserById(ctx.user.id, {
      user_metadata: { firstName: input.firstName, lastName: input.lastName },
    });
    return { success: true };
  }),
```

### Changement de mot de passe — client-side uniquement

```ts
// Dans ProfileSettings.tsx ("use client")
import { createClient } from "@/lib/supabase/client";

const handlePasswordChange = async (newPassword: string) => {
  const supabase = createClient();
  const { error } = await supabase.auth.updateUser({ password: newPassword });
  if (error) {
    toast.error("Impossible de modifier le mot de passe. Réessayez.");
  } else {
    toast.success("Mot de passe mis à jour.");
    resetPasswordForm();
  }
};
```

> **Sécurité** : `supabase.auth.updateUser()` exige une session active valide — pas besoin de demander l'ancien mot de passe pour le MVP. Supabase valide que l'utilisateur est bien authentifié.

### Schéma Prisma — Company et User

```prisma
model Company {
  id        String   @id @default(uuid())
  name      String
  siren     String   @unique  // 9 chiffres — lecture seule côté settings
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

model User {
  id        String   @id  // = Supabase Auth UUID
  email     String   @unique
  firstName String
  lastName  String
  companyId String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

### Points critiques — pièges à éviter

1. **Ne pas modifier `siren`** dans `updateCompany` — seul `name` est modifiable (AC 2)
2. **Ne pas créer de procédure de suppression d'utilisateur** — AC 8 dit "ne pas pouvoir se supprimer" par omission de la fonctionnalité
3. **Email en lecture seule** — `supabase.auth.updateUser({ email })` déclenche un flow de confirmation Supabase que le MVP ne gère pas. Afficher l'email mais pas de formulaire d'édition
4. **`ctx.user.id`** est le UUID Supabase Auth (correspond à `User.id` en Prisma)
5. **SiteNavbar affiche `user_metadata.firstName`** — le `auth.updateProfile` DOIT syncer Supabase metadata, sinon le nom dans la navbar ne change pas avant reconnexion
6. **`protectedProcedure` n'est pas encore importé dans `auth.ts`** — ajouter l'import depuis `"../trpc"` en même temps que `router` et `publicProcedure`
