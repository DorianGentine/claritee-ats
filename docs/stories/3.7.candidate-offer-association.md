# Story 3.7: Candidate-Offer Association (Candidature)

## Status

DONE

## Story

**As a** recruiter,
**I want** to associate candidates with job offers,
**so that** I can track which candidates are being considered for which positions.

## Acceptance Criteria

1. Sur la fiche offre `/offers/[id]`, le clic sur le bouton **"Associer un candidat"** ouvre un sélecteur de candidats (modal ou panneau latéral)
2. Le sélecteur de candidats permet de **rechercher / filtrer** dans la liste des candidats du cabinet (nom, titre/position au minimum)
3. Il est possible de **sélectionner un ou plusieurs candidats** dans le sélecteur pour les associer en une seule action
4. Chaque association crée un enregistrement **`Candidature`** en base, lié à l'offre et au candidat
5. Le **statut par défaut** d'une nouvelle candidature est `Contacté sur LinkedIn` (valeur existante dans l'enum des statuts de candidature)
6. Il est **impossible d'associer deux fois le même candidat à la même offre** (contrainte d'unicité côté base + gestion d'erreur côté UI)
7. Une candidature nouvellement créée est visible à la fois :
   - dans la **section Candidats** de la fiche offre (Story 3.6)
   - et dans la fiche candidat `/candidates/[id]` (section "Offres associées" ou équivalent)
8. Le modèle `Candidature` contient au minimum : `id`, `candidateId`, `offerId`, `status`, `createdAt`, `updatedAt`
9. La **date de création** de la candidature (champ `createdAt`) est correctement initialisée et conservée pour pouvoir retracer la date d'association
10. Le flux de sélection autorise une **association en masse** (bulk) : plusieurs candidats peuvent être sélectionnés avant validation, créant plusieurs candidatures en une seule action utilisateur

**Réf.** PRD § Epic 3, Story 3.7 ; Architecture §5 (Candidature), §9 (router `offer` – candidatures) ; Design System §2 (statuts candidature, badges) ; Wireframes §5 (bouton "Associer un candidat" sur la fiche offre, sélecteur de candidats).

> Note :
> - La **gestion du changement de statut** de candidature (dropdown, historique, filtres par statut, dissociation) est couverte par la **Story 3.8** et ne doit pas être implémentée ici, au-delà du statut initial par défaut.
> - La **section Candidats** de la fiche offre et l'affichage des badges statut, préparés en Story 3.6, sont réutilisés dans cette story.
> - Cette story se concentre sur la création et la visibilité des candidatures (associations candidat–offre) et sur le flux d'association (UI + API).

### Data Models

- **Candidature** (rappel / complétion) :
  - `id` (UUID)
  - `candidateId` (FK `Candidate`)
  - `offerId` (FK `JobOffer`)
  - `status` (`CandidatureStatus`) – valeurs alignées avec Design System §2
  - `createdAt`, `updatedAt`
  - Contrainte d'unicité `(candidateId, offerId)`
- **Relations** :
  - `Candidate` ↔ `Candidature` ↔ `JobOffer` (relations déjà exploitées en Story 3.6 pour la fiche offre).

### API Specifications

- **Mutation d'association candidats–offre** (`offer.addCandidates`) :
  - Input : `{ offerId: z.uuid(), candidateIds: z.array(z.uuid()).min(1) }`
  - Comportement :
    - Vérifie que l'offre et chaque candidat appartiennent au `companyId` courant.
    - Déduplique les `candidateIds` avant création.
    - Crée une candidature par `candidateId` manquant, avec `status = CONTACTED_LINKEDIN` via `createMany { skipDuplicates: true }`.
    - Retourne `{ count: number }` (nombre de candidatures effectivement créées).
    - Retourne `CONFLICT` si tous les candidats étaient déjà associés.

### UI & Components

- **Sélecteur de candidats** (`CandidateSelectDialog`) :
  - Charge les 100 premiers candidats via `candidate.list { limit: 100 }`, filtrage client-side par nom/titre.
  - Candidats déjà associés à l'offre grisés et non sélectionnables (`existingCandidateIds` passé en prop).
  - Réinitialisation du state (sélection + recherche) à chaque fermeture.

- **Fiche candidat** :
  - `CandidateCandidaturesSection` : section "Offres associées" extensible pour 3.8.
  - `candidate.getById` étendu pour inclure `candidatures { jobOffer { id, title } }`.
