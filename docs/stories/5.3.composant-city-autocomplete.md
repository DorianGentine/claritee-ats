## Story

**As a** developer,
**I want** a shared `CityAutocomplete` component,
**so that** all forms can pick cities consistently without duplicating logic.

## Acceptance Criteria

1. Composant `src/components/shared/CityAutocomplete.tsx` créé
2. Props : `value: CityOption | CityOption[] | null`, `onChange`, `mode: "single" | "multi"`, `placeholder?`, `disabled?`  
   (`CityOption = { id: string; name: string; region?: string | null; country: string }`)
3. Basé sur `Popover` + `Command` (shadcn Combobox pattern), debounce 300ms
4. Minimum 3 caractères pour déclencher la recherche — affiche "Saisir au moins 3 caractères" sinon
5. État chargement pendant la query (`isLoading` → spinner ou "Recherche...")
6. `mode="single"` : ville sélectionnée affichée comme badge clearable ; re-clic sur le badge → efface la sélection
7. `mode="multi"` : chaque ville sélectionnée apparaît comme chip ordonné avec boutons ↑, ↓ et × ; ↑ désactivé sur index=0, ↓ désactivé sur le dernier
8. Chaque option de liste : nom de la ville en texte principal + `Région · Pays` en `text-muted-foreground` dessous
9. Ville déjà sélectionnée : absente des suggestions (filtre côté client)
10. État vide : "Aucune ville trouvée"
11. Tests unitaires : mode single sélection + clear ; mode multi ajout + suppression + ↑ + ↓

## Tasks / Subtasks

- [ ] Task 0 — Pré-requis
  - [ ] Vérifier que la story 5.2 est DONE (procédure `city.autocomplete` disponible)
  - [ ] Lire `src/components/shared/` pour connaître les composants partagés existants
  - [ ] Consulter `docs/design-system.md` (palette, shadcn, typographie)
  - [ ] Vérifier que `useDebounce` existe dans le projet — sinon l'implémenter ou installer `use-debounce`

- [ ] Task 1 (AC: 1–3) — Créer la structure du composant
  - [ ] Créer `src/components/shared/CityAutocomplete.tsx`
  - [ ] Définir le type `CityOption = { id: string; name: string; region?: string | null; country: string }`
  - [ ] Définir les props avec union sur `mode` :
    ```ts
    type Props =
      | { mode: "single"; value: CityOption | null; onChange: (city: CityOption | null) => void; placeholder?: string; disabled?: boolean }
      | { mode: "multi"; value: CityOption[]; onChange: (cities: CityOption[]) => void; placeholder?: string; disabled?: boolean }
    ```
  - [ ] Implémenter le debounce sur le champ de saisie (300ms)
  - [ ] Appeler `trpc.cities.autocomplete.useQuery({ q: debouncedQuery }, { enabled: debouncedQuery.length >= 3 })`

- [ ] Task 2 (AC: 4–5) — Popover + Command (liste de suggestions)
  - [ ] Utiliser `<Popover>` + `<PopoverTrigger>` + `<PopoverContent>` (shadcn)
  - [ ] Intérieur du Popover : `<Command>` + `<CommandInput>` (affiche la query en cours) + `<CommandList>`
  - [ ] Si `debouncedQuery.length < 3` → `<CommandEmpty>Saisir au moins 3 caractères</CommandEmpty>`
  - [ ] Si `isLoading` → `<CommandEmpty>Recherche...</CommandEmpty>`
  - [ ] Suggestions filtrées (sans les villes déjà sélectionnées) : `<CommandItem>` pour chaque résultat
  - [ ] Chaque `<CommandItem>` : ligne principale = `city.name`, ligne secondaire = `city.region · city.country` (muted)

- [ ] Task 3 (AC: 6) — Mode single
  - [ ] Trigger du Popover : badge terracotta affichant le nom de la ville sélectionnée + bouton × ; ou bouton "Sélectionner une ville" si null
  - [ ] Clic sur une suggestion : appelle `onChange(city)` et ferme le Popover
  - [ ] Clic sur × du badge : appelle `onChange(null)`

- [ ] Task 4 (AC: 7) — Mode multi (chips + ↑↓)
  - [ ] Liste des chips sélectionnés affichée **au-dessus** du trigger Popover
  - [ ] Chaque chip : nom de la ville + bouton ↑ + bouton ↓ + bouton ×
  - [ ] ↑ : swapper la ville avec celle d'index − 1 → `onChange([...reordered])`
  - [ ] ↓ : swapper la ville avec celle d'index + 1 → `onChange([...reordered])`
  - [ ] ↑ sur index=0 : désactivé (`disabled`)
  - [ ] ↓ sur dernier index : désactivé (`disabled`)
  - [ ] × : supprimer la ville du tableau → `onChange(filtered)`
  - [ ] Clic sur une suggestion : appender la ville → `onChange([...value, city])`

- [ ] Task 5 (AC: 11) — Tests unitaires
  - [ ] Créer `tests/unit/components/shared/CityAutocomplete.test.tsx` (`/** @vitest-environment jsdom */`)
  - [ ] `afterEach(() => cleanup())`
  - [ ] Mode single : sélectionner une ville → `onChange` appelé avec la ville ; clic × → `onChange(null)`
  - [ ] Mode multi : sélectionner 2 villes ; cliquer ↑ sur la 2e → ordre inversé ; cliquer × sur la 1re → retirée
  - [ ] Mode multi : ↑ désactivé sur index=0, ↓ désactivé sur dernier

### Previous Story Insights

- Story 5.2 terminée : `trpc.cities.autocomplete` disponible
- Le projet utilise shadcn/ui `Popover` + `Command` pour le pattern Combobox (voir `src/components/ui/`)

### Component Specifications

- **Debounce :** si `useDebounce` n'existe pas encore dans le projet, utiliser le pattern `useState` + `useEffect` avec `setTimeout` plutôt que d'ajouter une dépendance. Si `use-debounce` est déjà dans `package.json`, l'utiliser.
- **Popover width :** `w-(--radix-popover-trigger-width)` sur `<PopoverContent>` pour aligner la largeur sur le trigger (convention projet CLAUDE.md)
- **Chips mode multi :** utiliser `<Badge variant="secondary">` ou un composant `<div>` stylé en flexbox avec `gap-1` — rester cohérent avec les chips de tags existants dans le projet
- **Boutons ↑↓ :** utiliser `<Button variant="ghost" size="icon">` avec `ChevronUp` / `ChevronDown` de `lucide-react`

### Technical Constraints

- Pas de `console.log` — uniquement `console.error` si besoin
- `isLoading` (pas `isFetching`) pour l'état skeleton/loading (convention CLAUDE.md)
- `"use client"` requis sur ce composant (interactivité)
- Le composant ne doit pas gérer le `order` en interne : il expose `CityOption[]` dans l'ordre courant du tableau — c'est le parent qui décide de l'`order` à persister
