## Ce qui a bien marché

- **Foundation solide dès le départ.** Le pattern multi-tenant `companyId` + RLS a été posé en Story 1.2 et n'a jamais été remis en question dans les epics suivants — zéro fuite de données inter-cabinets sur 29 stories.
- **CI/CD opérationnel dès Story 1.1.** Les stories suivantes ont toutes bénéficié du filet de sécurité lint + tsc + build sans effort supplémentaire.
- **Système d'invitation enrichi au-delà des specs (Story 1.5).** Badges de statut, tri, "Copy link" — l'implémentation a amélioré la spec initiale, ce qui a été le premier signe d'une bonne dynamique spec → implémentation.
- **Tests d'accessibilité intégrés (Story 1.7).** jest-axe posé dès le layout shell.

---

## Défis & zones d'amélioration

- **Prisma 7 breaking change (Story 1.1).** La datasource URL doit être dans `prisma.config.ts` et non dans `schema.prisma` — ce n'est pas documenté clairement dans le changelog Prisma. A coûté du temps non prévu.
- **UUID cast operators pour RLS (Story 1.2).** La mise en place des politiques RLS sur Supabase a nécessité des casts UUID non évidents. Documenté dans `docs/architecture/rls-policies.sql`.
- **Échappement `$` dans DATABASE_URL (Story 1.3).** Un caractère spécial dans le mot de passe de la base a cassé la migration silencieusement. Documenté en dev notes Story 1.3.
- **SMTP non configuré (Story 1.3).** La limite Supabase de 2 emails/heure sur le tier gratuit a été découverte en implémentation. Compromise temporaire acceptable pour le MVP.
- **Rate limiting non étendu aux mutations métier.** Seules les routes auth (login, register) et upload ont du rate limiting. Toutes les mutations candidats/offres/notes en sont exempts. → Adressé en Story 4.9.

---

## Insights clés

1. **Concentrer les risques stack au début.** Utiliser plusieurs nouvelles versions majeures simultanément (Prisma 7, tRPC v11, Next.js 16, React 19) dans la Story 1.1 a maximisé les surprises au pire moment. À l'avenir : spike technique isolé sur les dépendances à risque avant la Story 1.1.
2. **RLS = documentation obligatoire.** Les politiques RLS ne sont pas auto-documentées. Le fichier `rls-policies.sql` a été une bonne décision.
3. **La CI/CD dès Story 1 est un investissement rentable immédiatement.** Aucun coût humain n'a été engagé à déboguer des erreurs TypeScript ou lint sur les stories suivantes.
